How to use your API key

1) First, the Arena login (one time)

This server answers chats through your own Arena account in a browser it keeps on this machine. Before the first chat, log in once:

npm run login

A browser window opens on arena.ai — log in there (Google or email) and close nothing; the script saves the session by itself. If chats later start failing with "LOGIN_REQUIRED", just run it again. Arena has no official API and no anonymous chat, so this login is what everything stands on.

2) Reach this server — local

Start it with npm start. While it runs on this computer, your apps use:

  • Dashboard: this page
  • Chat endpoint: POST /api/chat
  • Models list: GET /api/models

From another device on the same Wi-Fi, replace localhost with this computer's local IP address. This wrapper is built to run locally — Arena's protections (Cloudflare + reCAPTCHA) punish datacenter servers, which is exactly why the research says the surviving wrappers run on a home machine.

3) Two kinds of key — which one to use

  • Fixed key (set as ARENA_API_KEY when starting the server): one key that always works. Best for your own apps — set it once and forget it.
  • Created keys (made on this page): one key per app or person, revocable anytime. Stored in keys.json on this machine.

Send the key as a header: Authorization: Bearer YOUR_KEY (or x-api-key: YOUR_KEY). A wrong or revoked key gets 401. If the server was started with ALLOW_KEYLESS_CHAT=true, sending no key also works — a wrong key still gets 401.

4) Send a chat

POST /api/chat
Authorization: Bearer YOUR_KEY
Content-Type: application/json

{
  "message": "What is 2+2? Answer with just the number",
  "model": "gpt-6-luna-max"
}

Reply:

{
  "status": "success",
  "reply": "4",
  "model_used": "gpt-6-luna-max",
  "model_id": "…",
  "conversation_id": "…"
}

Continue the same conversation: send the returned conversation_id back in your next request and the model remembers the context. Omit it to start fresh.

6) Images — send one, and get one created

Send an image (vision models only — the models table below marks them): add "image" with a data URL, or "images" with a list of data URLs. The server uploads the image to Arena's own storage the same way the website does, then attaches it to your message. Max 10 MB per image.

{
  "message": "What is in this picture?",
  "model": "gpt-6-luna-max",
  "image": "data:image/png;base64,iVBORw0KGgo..."
}

Create an image (image models only): add "generateImage": true and describe the picture in "message". The created image comes back in the reply's images list — each entry has a url and/or a data_url:

{
  "message": "A red bicycle on a beach at sunset",
  "model": "<an image model from /api/models>",
  "generateImage": true
}
{
  "status": "success",
  "reply": "",
  "images": [{ "url": "https://…", "mime_type": "image/png" }],
  "model_used": "…",
  "conversation_id": "…"
}

Asking a model for something it cannot do fails fast with a clear error (IMAGE_NOT_SUPPORTED) instead of silently dropping your image.

Create a video: add "generateVideo": true and describe the video in "message". There is no model selection for video — any "model" you send is ignored and the server picks a random video model (veo, sora, kling and friends) for each new video; the reply's model_used tells you which one was drawn. The video itself comes back in the reply's videos list (url / data_url). The model list comes from Arena's full model catalog, so video and image models are all included — that catalog is also what the filters above use.

7) JavaScript (browser / Node)

const res = await fetch("/api/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer YOUR_KEY"
  },
  body: JSON.stringify({ message: "Hello!", model: "gpt-6-luna-max" })
});
const data = await res.json();
console.log(data.reply);

8) Python

import requests

r = requests.post(
    "/api/chat",
    headers={"Authorization": "Bearer YOUR_KEY"},
    json={"message": "Hello!", "model": "gpt-6-luna-max"},
    timeout=120,
)
print(r.json()["reply"])

9) Honest limits (from the wrapper research)

  • Arena can change its site and break every wrapper — it has happened several times. When it breaks, this server returns a clear error code instead of hanging.
  • Your Arena account's own limits apply (daily credits for Direct mode). Don't hammer it — rapid-fire requests earn ~20-minute cooldowns.
  • Keep the server browser and the login on the same machine/IP — the reCAPTCHA tokens are bound to both.
  • There is no tool-calling (function calling) through Arena — plain chat in, text out (images Arena creates are returned in images when a model produces them).
